1 Google Analytics — Traffic Data

This connects your GA4 properties to the dashboard so it can show sessions, organic traffic, bounce rate, new vs returning users, and conversion data — compared to last month and last year.

1
Developer creates a Google Cloud Project & Service Account
Developer

A service account is a robot email address that the dashboard uses to read data from Google APIs. It has no password and can only do what you explicitly allow.

  1. Go to console.cloud.google.com and sign in with the agency Google account
  2. Click New Project → name it "Agency Analytics Dashboard"
  3. Go to APIs & Services → Library
  4. Search and enable: "Google Analytics Data API"
  5. Also enable: "Google Search Console API"
  6. Go to IAM & Admin → Service Accounts → Create Service Account
  7. Name it: analytics-dashboard → click Create
  8. Skip the optional steps → click Done
  9. Click the new service account → Keys tab → Add Key → JSON
  10. A JSON file downloads — store it securely (this is the credential file)

Developer then sends the SEO Director this email address (found in the JSON file):

Service Account Email: analytics-dashboard@agency-analytics.iam.gserviceaccount.com # This email gets added to every GA4 property and Search Console site
2
SEO Director adds service account to every GA4 property
SEO Director

This must be done for every client property that needs to appear in the dashboard. It gives the dashboard read-only access to that property's data.

  1. Log into analytics.google.com
  2. Select the first client property from the top dropdown
  3. Go to Admin (bottom left gear icon)
  4. Under Property column → click "Property Access Management"
  5. Click the blue + Add button (top right)
  6. Paste the service account email provided by the developer
  7. Set role to Viewer (read-only — safe)
  8. Click Add
  9. Repeat for every client property
💡

For 800+ properties (bulk method): Instead of doing this manually, ask the developer to write a script using the GA4 Admin API that adds the service account to all properties at once. Provide the developer with a spreadsheet of all GA4 Property IDs (found in GA4 → Admin → Property Settings → Property ID — a 9-digit number).

2 Keyword Rankings — Google Search Console

Google Search Console is the official, free, and most accurate source for keyword rankings. It shows exactly which keywords your pages rank for, their position, clicks, and impressions — sourced directly from Google.

FREE

Google Search Console API

Official Google source. Shows keywords ranking for each property, position, clicks, impressions, and CTR. Best starting point.

  • Query (keyword)
  • Average position
  • Clicks & Impressions
  • Click-through rate
  • Ranking URL (which page ranks)
PAID ADD-ON

SEMrush / Ahrefs / SE Ranking

Third-party tools that add competitor keyword data, search volume, keyword difficulty, and historical tracking.

  • Competitor keyword gaps
  • Search volume per keyword
  • Keyword difficulty score
  • Position history over time
✅

Recommendation: Start with Google Search Console (free). Once the dashboard is live, layer in SEMrush or Ahrefs for competitor tracking and search volume. The dashboard is already built to display both.

4
SEO Director adds service account to every Search Console property
SEO Director

The same service account email used for GA4 also gets added to Search Console. This gives the dashboard access to keyword ranking data for each hotel website.

  1. Go to search.google.com/search-console
  2. Select the first client website from the property dropdown
  3. Click Settings (gear icon, left sidebar)
  4. Click "Users and permissions"
  5. Click "Add User"
  6. Paste the service account email
  7. Set permission to Full (required for reading query/keyword data)
  8. Click Add
  9. Repeat for every client website
⚠️

Note: The Search Console property must be verified (green tick) for the data to be accessible. If any client site is unverified, work with the developer to complete domain verification first. Common methods: Google Tag Manager, DNS record, or HTML file upload.

Credentials are stored in a .env.local file — this is never committed to GitHub. The developer creates this file inside the seo-dashboard/ folder:

🔐

Security: The .env.local file must never be shared publicly or committed to GitHub. It contains secret credentials. The developer adds it to .gitignore to prevent accidental uploads.

9
Developer sets up the database (Supabase)
Developer

A database stores all the analytics data so the dashboard loads instantly without calling Google APIs on every page view. The recommended free database is Supabase.

  1. Go to supabase.com → Create a free account
  2. Create a new project → name it "analytics-dashboard"
  3. Copy the Project URL and Anon Key into .env.local
  4. Developer creates the database tables for properties, metrics, and keywords

The database structure the developer builds:

TableWhat it stores
propertiesAll 800+ property names, GA4 IDs, Search Console URLs, chain grouping
daily_metricsTraffic, bounce rate, conversions, room nights, revenue per property per day
keyword_rankingsKeyword, rank, previous rank, URL, property ID — updated daily
competitorsCompetitor domains mapped to each property
10
Developer builds the nightly data sync job
Developer

This is the most critical piece. A scheduled job runs automatically every night at midnight and refreshes all data for 800+ properties. The dashboard then reads from the database — making it fast and reliable.

The sync job does this every night:

  1. Loops through all 800+ properties from the database
  2. Calls GA4 API for each property → gets sessions, organic traffic, bounce rate, conversions, new vs returning users
  3. Calls Search Console API for each property → gets keyword positions, clicks, impressions
  4. Calculates the vs Last Month % and vs Last Year % change
  5. Assigns status (critical / warning / healthy) based on traffic trends
  6. Saves everything to the database
  7. Dashboard displays fresh data the next morning
⏱

Why nightly? Calling GA4 API for 800+ properties in real-time would take too long and hit rate limits. The nightly sync pre-fetches everything and stores it — so the dashboard loads in under 1 second regardless of how many properties you have.

11
Developer deploys the dashboard to Vercel
Developer

Vercel is a free hosting platform built for Next.js. It gives you a live URL you can open from any device.

  1. Go to vercel.com → Sign in with GitHub
  2. Click Import Project → Select the parvinderdhillon90/seo repository
  3. Set the Root Directory to seo-dashboard
  4. Add all environment variables from .env.local in the Vercel settings panel
  5. Click Deploy
  6. Vercel gives you a URL: https://agency-analytics.vercel.app

From this point, every time the developer pushes code to GitHub, the live dashboard updates automatically.

13
SEO Director / Operations provides booking engine credentials
SEO Director

Securely share the following with the developer (use a password manager like 1Password or a secure note — never email credentials):

  • Booking engine name and version
  • API key or OAuth credentials
  • API documentation URL
  • Which metrics to pull: room nights booked, total revenue, booking date, check-in date

If using the CSV method: set up a shared Google Drive folder where hotel managers drop the daily report file each morning. The developer's sync job picks it up automatically.

14

Everyone

Before connecting all 800+ properties, test with one chain (10–15 properties) to confirm everything works correctly.

  1. SEO Director adds service account to one chain's GA4 properties and Search Console sites
  2. Developer connects just those properties and runs the sync job
  3. You review the dashboard — verify the numbers match what you see in GA4 directly
  4. Check: organic traffic ✓ vs last month % ✓ keyword positions ✓ new/returning users ✓
  5. If everything looks correct → proceed to full rollout

Full rollout to all properties
Everyone

Once the pilot is confirmed working:

  1. SEO Director (or developer's bulk script) adds service account to all remaining GA4 properties
  2. SEO Director adds service account to all remaining Search Console sites
  3. Developer runs the full nightly sync for all 800+ properties
  4. Dashboard goes live with real data at the Vercel URL
  5. You access the dashboard from any browser, anywhere

❓ Frequently Asked Questions

Q
Is this safe? Will clients' data be exposed?

The service account has read-only (Viewer) access — it cannot change any settings, create reports, or delete anything in GA4. It can only read the data. The dashboard is password-protected via Vercel's access controls. No client data is shared with third parties.

Q
Does this cost anything?

Google APIs: Free (GA4 Data API and Search Console API are free for standard usage volumes).
Supabase: Free tier covers up to 500MB database — more than enough for 800 properties.
Vercel: Free tier covers the dashboard hosting.
SEMrush/Ahrefs: Optional paid add-on for competitor data and search volume. Not required to go live.

Q
How accurate are the keyword positions from Search Console?

Very accurate — it comes directly from Google. The position shown is the average ranking position over the selected date range. For a single day, it reflects exactly where your page appeared in Google search results. Note: Search Console data has a 2–3 day delay before it appears in the API.

Q
What if a client does not have Search Console set up?

The developer can help set up Search Console verification for any missing properties. Common methods: adding a Google Tag Manager tag (easiest if GTM is already on the site), adding a DNS TXT record, or uploading an HTML verification file to the server. The SEO Director should identify which client sites are missing and prioritise verification.

Q
Can the team download reports to send to clients?

Yes. The Reports & Crux page has a Download PDF button and a Copy to Clipboard button. Select the chain or specific property, and the system auto-generates an executive summary with traffic analysis, keyword performance, conversion insights, and prioritised recommendations — ready to send to the client as-is or with minor edits.
